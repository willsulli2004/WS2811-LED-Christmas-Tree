# 🎄 Christmas Tree LED Controller

A Raspberry Pi 5 project for driving 150 WS2811 addressable LED pixel lights with spatially-aware animations. LEDs are mapped to physical x,y coordinates using a camera and computer vision, enabling realistic effects like sweeping wipes and transitions that follow the actual shape of the tree. Integrates with Homebridge for smart home control.

---

## Features

- **Camera-based LED mapping** — automatically determines the physical position of each LED using image processing
- **Coordinate-aware animations** — effects like top-to-bottom wipes and side-to-side sweeps use real spatial data, not just sequential order
- **Flask HTTP API** — control the lights from any device on your local network
- **Homebridge integration** — expose the tree as a smart home accessory via `homebridge-http-switch`
- **Graceful shutdown** — clean LED power-off on server stop

---

## Hardware Requirements

| Component | Details |
|---|---|
| Raspberry Pi 5 | Any RAM variant |
| WS2811 addressable LEDs | 150 pixels (ALITOVE or equivalent) |
| 5V external power supply | Minimum 5A recommended (150 LEDs × 60mA max = 9A at full white) |
| Level shifter (optional) | 3.3V → 5V logic; many WS2811 strips work without one |
| Camera | Any camera accessible via HTTP snapshot URL |

> **Power note:** The Pi's GPIO cannot supply enough current for the LEDs. An external 5V supply is required. Connect grounds between the Pi, power supply, and LED string.

---

## Software Requirements

- Raspberry Pi OS (64-bit recommended)
- Python 3.x
- The following Python packages:

```bash
sudo pip3 install rpi_ws281x adafruit-circuitpython-neopixel flask requests pillow numpy --break-system-packages
```

> The `--break-system-packages` flag is required on Raspberry Pi OS due to the externally managed Python environment.

## Prerequisites

### Homebridge (Required for Smart Home Integration)

This project assumes you already have **Homebridge** running on your network — either on this same Pi or another device. Homebridge is not included here and must be set up separately before the smart home integration will work.

- [Homebridge installation guide](https://github.com/homebridge/homebridge/wiki)
- Once Homebridge is running, install the **homebridge-http-switch** plugin through the Homebridge UI or via:

```bash
npm install -g homebridge-http-switch
```

Then add an accessory entry in your Homebridge `config.json` pointing to this server's IP and port (see [Configuration](#homebridge-configuration) below).

## Setup & Usage

### Step 1: Wire the Hardware

- Connect the LED data line to **GPIO 18** (physical pin 12)
- Connect the external 5V supply to the LED VCC and GND
- Connect Pi GND to the power supply GND (common ground)

### Step 2: Map LED Positions

Point your camera at the tree so all LEDs are visible, then run the mapping script. It will light each LED one at a time, capture a snapshot, find the brightest point, and record its x,y coordinate.

```bash
sudo python3 map_leds.py
```

This generates `led_coordinates.json` with entries like:

```json
{
  "0":  { "x": 405.0, "y": 393.8 },
  "1":  { "x": 312.4, "y": 201.6 },
  ...
}
```

> Run this once per season, or any time LEDs are rearranged. The mapping script temporarily takes exclusive control of the LEDs — stop the Flask server first if it's running.

### Step 3: Start the Server

```bash
sudo python3 server.py
```

The server starts on port `5000` and accepts requests from any device on your local network.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/on` | Turn lights on (last used animation) |
| GET | `/off` | Turn all lights off |
| GET | `/status` | Returns `{"state": "on"}` or `{"state": "off"}` |
| GET | `/animation/<name>` | Switch to a named animation |

## Homebridge Configuration

Add the following to the `accessories` array in your Homebridge `config.json`. Replace `<PI_IP>` with the IP address of the Pi running this server.

```json
{
  "accessory": "HTTP-SWITCH",
  "name": "Christmas Tree",
  "switchType": "stateful",
  "onUrl": "http://<PI_IP>:5000/on",
  "offUrl": "http://<PI_IP>:5000/off",
  "statusUrl": "http://<PI_IP>:5000/status",
  "statusPattern": "\"on\""
}
```

After saving, restart Homebridge. The tree will appear as a switch in the Home app.

## Animations

Animations use the `led_coordinates.json` map to drive spatially-aware effects. Available animations include:

- **horizontal_wipe** — sweeps a line of light top-to-bottom or bottom-to-top
- **vertical_wipe** — sweeps left-to-right or right-to-left
- **twinkle** — random twinkling white stars
- **candy_cane** — chasing red and white stripes
- **northern_lights** — green/blue aurora wave
- **fire_flicker** — warm orange glow
- **christmas_wave** — red, green, and gold flowing bands
- **snowfall** — white dots drifting on a dark background

## Troubleshooting

**"GPIO busy" error on startup**
Try a different GPIO pin (e.g. GPIO 10 or GPIO 21) and update `board.D18` in the scripts accordingly.

**LEDs not responding or flickering**
- Verify the external power supply is connected and capable of delivering enough current
- Check that Pi GND and power supply GND share a common connection
- Some WS2811 strips require a level shifter for reliable 3.3V → 5V logic translation

**Mapping script finds no bright pixels**
- Increase ambient darkness — the script works best in a dim room
- Lower the `THRESHOLD` value in `map_leds.py` (default: 200)
- Verify the camera URL returns a valid image: `curl http://<CAMERA_IP>:<PORT>/snapshot --output test.jpg`

**Homebridge not reflecting state correctly**
- Confirm the Flask server is running and accessible from the Homebridge host
- Test endpoints manually: `curl http://<PI_IP>:5000/status`

## Notes

- The Pi also runs Pi-hole DNS on the same device. The Flask server on port `5000` does not conflict with Pi-hole services.
- For a lower-power permanent installation, migrating to a **Raspberry Pi Pico 2** is feasible, though it requires porting from Python/`rpi_ws281x` to MicroPython/`neopixel` and gives up the camera-mapping workflow.
